Deployed to the existing Last Stop Vercel project and the user-created Neon project `damp-smoke-94581569`. Source is in `jenschristianschroder/Last-Stop`.

## Passed

- Production Next.js build and TypeScript checks.
- All 15 engine tests, including private projections, clue acquisition, sabotage, voting, stored deadlines, reconnection, and a complete rehearsal.
- Case validator: 12,325 terminal histories of the stated coordinated policy against legal sabotage/hostile-work sequences; zero failing histories, proof by round five. This is not evidence of human win rates.
- Browser on the production URL: boarding, guide, private dossier, investigation action, acquired clue, voluntary publication, private notes, page reload/reconnection, phase progression, sealed ballot with weapon/scene, and final five-investigator verdict.
- Six independent live HTTP sessions: room creation/retry, five guests joining, host approvals, unauthorized read rejection, and rejection of a seventh passenger.
- Corrected perspective-art overflow, then measured the page within the desktop viewport.
- No runtime errors or warnings observed on the verified release after explicitly configuring full database TLS verification.
- Built browser assets checked for unreleased clue text and the private reveal narrative; neither was bundled.

## Limits and next validation

The extended six-session HTTP test stopped at the workspace network proxy before ready/start; it did not complete a live six-human match. The complete flow was verified in a browser using the clearly labelled rehearsal and in deterministic engine tests. Mobile layout is implemented but has not been visually tested at phone viewport sizes in this environment. Run a six-person playtest to assess comprehension, enjoyment, pacing, and faction win rates.

The current case has a fixed solution, so it is a pilot for fresh players. The conductor question interface uses a deterministic keyword baseline with a visible suggested action and direct controls; no trained tiny/custom language model is deployed. Model development remains gated by labelled data, evaluation, and a measured benefit over this baseline.

The Vercel project was deployed through the connected deployment API. Automatic deployments on GitHub pushes are not connected because the Vercel GitHub integration is not installed for this project. Connect that integration to this repository to enable push-triggered deployments.
